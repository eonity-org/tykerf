# The editor

The editor is a small HTTP server (`src/editor/server.ts`, `src/editor/page.ts`) and two browser clients with no build step (`src/editor/public/`):
- **The shell** (`public/shell.html` and `public/shell/`): the editor people use. One bar, the page in a frame at its real width, tasks for Kaity, fixing one thing by hand, the site's sidebar and screens. It is a document of its own: the page in its frame is served exactly as it renders, and nothing is drawn inside it.
- **The full editor** (`public/tykerf.js`): the expert way beside tasks, every block in detail, shown as the shell's second mode (*Tasks | Full editor* in the bar, `?mode=full`). It is one script added to the page, which draws its panel inside a shadow root, so the site's CSS and the editor's CSS never touch.

**The browser never edits the tree.** It asks the server for named operations, and the server runs them through the same core library the MCP server uses, as author `user`. People and the AI work on one tree and one history.

## The server

`npm start -- <folder> [--port 4400] [--host <addr>] [--layout t --theme th --name p]`

The editor always serves a site (`siteKind`): a folder of pages, or a new or empty folder, which becomes one. Started on a page of a site (`siteOf`), it serves that site; a page folder in no site is refused, with the commands that put it in one. `--layout` on a new folder makes the site's home page, named `--name` or `HOME_PAGE` (`home`); on a site with pages, it adds the page `--name` names (`addSitePage`) unless the site has it already, and refuses without `--name`, so the same command run again only starts the editor; `newSitePage` makes a site's first page its home in `site.json`, whichever way it is made (New page, the CLI, MCP).
- **The site** serves each page at `/<page>/`, with a host per page made on first use (`hostOf`). For a signed-in person, `/<page>/` redirects to the shell, `/_tykerf/edit/<page>/`; the page itself is served as it is with `?tykerf=frame` (the shell's frame) or `?tykerf=hidden` (after *Hide tykerf*, with *Show tykerf* back), and with the full editor for `?tykerf=full-frame` (what the shell's Full editor mode loads in its frame). `?tykerf=full` and the older `?block=<name>&tab=<tab>` and `?edit` links redirect to `/_tykerf/edit/<page>/?mode=full`, on that block and tab. `/` redirects to the home page in `site.json`; without one, and at the old manager's address `/_tykerf/site/`, to the site's screens (`/_tykerf/edit/_site/tasks`, or New page on a site with no pages). `/pages/` is `siteIndex` and `/sitemap.xml` `siteMap` (with `TYKERF_PUBLIC_URL`). A removed page's open tabs go to the site's screens. `GET /_tykerf/site` also says what Kaity is doing (`kaity: {site, pages: [{page, block}]}`).
- **Pages made elsewhere.** The MCP server or the command line may add pages to the site while the editor runs (in an empty folder, MCP `use_layout` makes the home page, never a page in the folder itself). The site sidebar reads the site again whenever the window comes back into focus, so they show then. Pages renamed or removed from another process (Kaity's site run through MCP `rename_page`/`remove_page`) are in the site's `.tykerf/moves.jsonl` (`renamePage`/`removePage` write it, `pageMoves` reads it): `followMoves()` in `server.ts`, on the folder watcher (`watchSite`, which starts once the site's folder exists) and at the end of each site run, closes the moved page's host, so its open tabs go to the new address (or the site's screens), and refreshes the others.

`.env` is loaded from the working folder and the site or page folder. `runnerFromEnv()` then picks the AI runner once for the whole server.

Every operation runs inside `ws.transaction()`, then broadcasts `changed`. Changes from outside (the AI's MCP process, a text editor) reach open pages through the store's watcher.

### Code updates

The client files in `public/` are read from disk on every request, but the server process keeps the TypeScript it started with. `codeStamp()` (server.ts) fingerprints `src/**/*.ts` (count, sizes, latest change) at startup; `GET /_tykerf/version` says whether it differs now. `tykerf.js` and `start.html` ask on load and when the tab comes back, and show a restart notice when it does, or when the address is missing (a server older than this check).

The other way round, a page keeps the script it loaded: after an update and a restart, an open tab still runs the old `tykerf.js` (its event stream simply reconnects). `/_tykerf/version` also returns `page`, `pageStamp()` of `public/` (`TYKERF_PAGE_DIR` in tests); the page remembers the first one it gets and asks again when its event stream reconnects (the manager: when `/_tykerf/site` answers again after failing) and when the tab comes back. A different one shows *Reload this page…* with a **Reload** button; it never reloads by itself, so a draft isn't lost.

### Security

- The server listens on `127.0.0.1` by default.
- `foreign()` refuses:
  - other `Host` headers (against DNS rebinding);
  - changes from other origins, or without a JSON body (against cross-site requests).
- Every state-changing endpoint must stay behind `foreign()`.
- Page files are served with `Content-Security-Policy: sandbox`, and uploads are checked by their bytes.
- Box scripts run in the editor's own page and origin, so they can call the API too. That is a documented, accepted risk, explained in [SECURITY.md](../../../SECURITY.md).

## The shell

The editor people use is one **shell**: `public/shell.html`, at `/_tykerf/edit/<page>/` for a page (a page the site doesn't have is a 404) and at `/_tykerf/edit/_site/<screen>` for the site's screens (`server.ts`). `public/shell/boot.js` picks the mode: `shell.js` (a page in its frame, with `frame.js`) or `site.js` (the site); `common.js` holds what they share (`t`, `request`, the toast, `plainLabel`, the marks) and `screens.js` the site's screens. Plain ES modules like the rest of the client.

- **The page is in a frame**, at its own address with `?tykerf=frame`: `page.ts` serves it as it is, without `tykerf.js`. The frame is as wide as the window, under the bar, so the page lays out at its real width. `frame.js` is the only code that touches the page's document (same origin): it turns clicks into picks (links, buttons and forms don't react), finds the block and the element path (`inline.js`), measures elements, and swaps new content in place after a change (`/_tykerf/page`), as `reloadPage` does here. A change to the head reloads the frame.
- **Nothing is drawn inside the page.** Outlines, pins and the task box are in the shell's own document, in `.overlay` over the frame, placed from the elements' boxes in the frame and redrawn on its scroll, resize and content changes.
- **The bar** (`renderBar`): the page switcher (it opens the site sidebar), a hint or Kaity's status, the task count (opens the tray), **Give them to Kaity** (`POST /_tykerf/taskrun/start`; **Stop Kaity** while she works, **Keep what she did** after), **Undo** (its title names the step, task changes included) and **Hide tykerf**; after the page switcher, *Tasks | Full editor* (`.modes`) switches the shell's mode (the box being fixed goes along).
- **Full editor mode** (`FULL`, `?mode=full`): the frame loads `?tykerf=full-frame` (with the block and tab the address asked for, once), `frame.js` stays passive (no picks, no pins, no overlay), refreshes and jobs are the full editor's own, and the bar keeps the page switcher, the modes, the task count and Hide tykerf. Page cards in the sidebar and moves keep the mode (`shellOf`). Embedded (`EMBEDDED`, the `embedded` class on its host), the full editor's header is light with the tykerf sign, its words without icons except the theme presets' colour dots (`:host(.embedded)` rules at the end of `tykerf.css`; on its own it keeps the dark header). While the site sidebar is open (not folded) it compacts beside it: `layoutStage` calls the frame's `tykerfSidebar(edge)` with the sidebar's right edge in the frame's pixels (`sidebarEdge`, null when closed), and a full editor that loads with the sidebar open asks `window.top.tykerfSidebarEdge()` (unless it was opened on a block). `siteSidebar` keeps how the panel was (`bySite`) and compacts it with `setMin(true, false)`, which isn't remembered; closing puts it back. The person's own Compact / See more, or anything that opens the panel, ends it; a drag meanwhile is kept.
- **The task box** (`renderBox`) is anchored to the element clicked, in three rows: one line with the number (a button: it turns into *Question* by itself when the text ends with `?`, until the person clicks it to choose), the block (its tooltip: Kaity changes only it), the element in words (`plainLabel` of the task's label), a width chip only away from full width, and ×; the field, whose placeholder says what to write; **Kaity, do it now** (adds the task and hands over only it) and **Add task**. Everything else is in the right-click menu, which *More… or right-click* at the row's left opens from the box (`openMenu`'s `at`: the box stays, with its text, and the menu leaves out the task and the question; Escape closes only the menu) (Fix it by hand, *Ask a question here…* which opens it as a question, editing words, boxes). The picture button in the field's corner (or a paste or drop on the box) attaches up to 5 pictures, scaled down as Kaity's are (`shrinkImage` in `common.js`); `/tasks/add` keeps them as her attachments are (`AI.keepImage`, `.tykerf/images/`) and the task stores their names (`Task.images`), which `TaskRun` reads back (`AI.attachment`) and sends with the task.
- **The tray** (`renderTray`) lists the page's open tasks and questions as cards (with their pictures, `pics`), with *Show on the page*, *Mark done* (not for a question) and *Remove*. In Full editor mode the bar's task count is a link to Tasks: the tray is Tasks' own.
- **Kaity at work and the review** follow the task run's state (`setRun`, from `/_tykerf/state` and the SSE `taskrun` event). While she works the bar says *task i of n* with a chip for the task she is on, with **Stop Kaity**, **Undo all she did** (she stops first, then her work goes) and *Hide / Show the steps*; the tray opens by itself (unless the person closed it during the run) with one card per task (`runCard`): *now* with her latest step, *waiting* with *Take it off her list*, *done* with her summary. On the page her element is outlined with *n · Kaity is here* on its corner, and the page scrolls to it unless the person scrolled in the last 6 s (`followKaity`). When she stops, the bar sums the run up (`runSum`: "2 done, 1 answered, 1 needs you") with **Keep the n changes** (`/taskrun/keep`) and **Undo all she did**. A done task has a check that fits it (`check`: *See it on a phone* when it was written narrow or speaks of phones, which shows the frame at 375 px (`setDevice('phone')`); *Try the button* / *Try the link* for those elements, which lets the page react until *Done trying*, a link elsewhere only saying where it leads), *Before and after* (her pictures, in a dialog), *Undo this one*, *Ask for more* (a new task on the same element, given to her at once; during a run it joins her list) and *See her conversation on <block>* (`conversation`: the block's chat, `GET /_tykerf/chat`, read only in a dialog; also `?conversation=<block>`, the Kaity screen's links). What a task left unfinished (`RunTask.left`, from the `check` an `AI.ask` run with a tag now reports to `onEnd`) shows on its card (`leftNote`) with **Fix them** (`/taskrun/fix`: `TaskRun.fix` queues the task again with `fix`, and `fixLeft` runs `AI.fix` on that check under the task's tag, so *Undo this one* takes both) and **Leave them as they are** (`/taskrun/leave-left`, `AI.leave` on that check, `.tykerf/kept.json`). A task she needs the person for shows her question with an answer field, **Answer and continue** and *Leave it for later*; an answered question shows the question and her answer, *Ask a follow-up* and *Got it* (`/taskrun/seen`). Finished tasks' pins read *n done* until the review is kept.
- **The site sidebar** (`createSidebar` in `site.js`) opens from the page switcher, over the page (the frame doesn't move or resize). It stays until *Close*: a click on the page, a task box or the right-click menu leave it there, and a page opens with it as the last one left it (`restore`; `tykerf.sidebar`: `open`, `folded` or `closed`). *‹* folds it to a 22 px edge with *›* to open it again (`fold`); the fix panel puts it aside while it is open (`suspend`/`resume`); on a site screen it is docked beside it. It holds *Ask Kaity about the whole site* (`/_tykerf/site/ask`, then the Kaity screen), the pages as cards (name, address, Home, a status line: open now, tasks, things to check) with *Make it home*, *Name and title*, *Duplicate* and *Remove* (confirmed first, saying which pages' links to it will point nowhere: `/_tykerf/site/links`), *+ Page* (the site manager's chooser for now), the whole site's screens each with its state (`screenStates`, from `siteInfo`: tasks, shared blocks and boxes that could be, the check's count, media and pictures kept twice, links and pages hard to reach, Kaity's work, the language), then **Publish**, *Site history* and *Sign out*.
- **The site's screens** (`screens.js`), each drawn from the site's endpoints: *Tasks for Kaity* (every open task by page, **Give Kaity everything**, *Give Kaity this page*, and the check's fixes on a page's box added as tasks), *Shared blocks* (boxes that could be shared, each with *Share*, *Share all*, *Let Kaity decide which*; the shared blocks with their pages and slots, *Open it on* and *Leave a task*, which open the page with `?show=<box>` or `?task=<box>`; and the kit's other files as tabs, each file editable), *Check the site* (grouped by kind, *Kaity can fix* or *Yours to decide*, a fix on each row: titles, the language, the shared nav, the box; **Give Kaity the n she can fix** asks the site's Kaity with the list), *Media* (filters, pictures kept twice, *Move to the site*, *Remove* for an unused one), *Links between pages* (a headline in words, each page's links both ways, *Hard to reach*), *Kaity's work* (her conversation about the whole site, live over `/_tykerf/site/events`, and every run on the site), *Site history*, *Head code, icon & language* (with Kaity's status and *Test it*) and *Publish* (where to, publish now, and the exports: the site, the page it came from, to open from disk, with the kit's styles inlined or not).
- **Give Kaity everything** (`POST /_tykerf/site/tasks/give`, `{ pages }` for some; `/site/tasks/stop`) queues the pages with open tasks and starts each page's task run in turn (`nextQueuedPage` in `server.ts`, which hears every page's run through `createPageHost`'s `onTaskRun`); a run the person stopped stops the queue. The site's event stream says `taskrun` with the page, its run and the queue.
- **Fixing by hand** (`createFixPanel` in `fix.js`), from *Fix it by hand* in the right-click menu, opens a narrow sidebar on the element clicked; while it is open a click on the page picks the next thing to fix, and the bar says *Fixing by hand · …* with **Done, back to tasks**. A link or button shows its words and where it leads (*Nowhere yet*, a box of this page as `#sw-<box>`, a page of the site, another address, checked with `safeHref`), a heading or paragraph its words, a picture its description and *Choose another picture…* (`/_tykerf/asset`). A save reads the box again, maps the element to its code by its path (`atPath`) and writes it only when the code still has the element as the page shows it (`sameElement`, `sameImage`), else it says the box changed; an element that holds other elements, or that a script made, is fixed through the box's text or code. One line says whether the box is the same on another page (`identicalBoxes`) or is a shared block (every page that shows it). A box clicked as a whole shows all its text (`textFields`). *More, if the fix is bigger* links to the full editor on the box (`ctx.fullEditor(block, tab)`): Size & look, Text, Code, or the box itself to move, add or delete boxes. The quick fix has no copies of those editors. What the person has typed and not saved survives a refresh of the page. *Leave it as a task for Kaity* closes it and opens the task box on the element.
- **New page** (`newScreen` in `screens.js`, `/_tykerf/edit/_site/new`, from *+ Page* in the sidebar) is a screen of its own: no sidebar, and a bar with only the way back. It leads with Kaity (*Describe it*, up to 3 images or a design ZIP, the page name with its address, **Build it with Kaity**; the model is not named), with *What happens* beside it, then *Or start without Kaity*: a layout (chips, the chosen one described, *With the site's navigation and footer*, *Preview at full size*) or a copy of a web page with today's caution. All go through `POST /_tykerf/site/new` and open the new page in the shell. What is typed survives going to another screen and back (`draft`).
- **The page's job** (Kaity building a new page, or a copy being made: `GET /_tykerf/job`, SSE `job`) is the bar's status while it runs (her latest step, **Stop Kaity** / *Stop the copy*: `/_tykerf/job/stop`) and the tray's list of steps (`jobTitle`, `setJob`); when it ends the bar says how, until **Got it** (`/_tykerf/job/seen`).
- **The page's width** (`.widths` in the bar, `DEVICES`, `setDevice`; each button's size in a fixed-width label, the full-width one the zoom, so the box never changes width): full, a tablet held upright (768 px) or a phone (375 px), as `.stage.tablet` / `.stage.phone` narrowing `.viewport`; tasks written meanwhile take that width (`frame.width`); only the page takes it: the task box keeps its own width and may go past the column's sides (`placeBox` keeps it on the stage); shrink to fit applies at full width only; Escape goes back to full width.
- **Over the page / Shrink the page to fit**, at the top of both sidebars (`modeSwitch`, remembered as `tykerf.sidebarMode`): shrunk, the page keeps its real width (nothing reflows) and `.viewport` is scaled into the room beside the sidebar (`layoutStage`), the overlay with it (outlines and pins line up with the page); the task box is drawn back at its own size (`placeBox`: `scale(1/zoom)`, placed by that size); the bar's full-width button says the zoom. Never in Full editor mode (`FULL`): the full editor's panel is inside the frame and would shrink with the page, so the sidebar is over the page there and its switch shows *Shrink* greyed out with why (`aria-disabled`, `NO_SHRINK`).
- **The second button** on the page (`openMenu`; `frame.js` reports the right-click with the element under it): *Leave a task here…*, *Ask a question here…*, *Edit this text* (also a double click, `dblpick`, which drops the first click's empty task box; an element with words only: `frame.editText` makes it `contenteditable="plaintext-only"` in the page, Enter or a click elsewhere keeps the words, Escape puts them back; the shell writes them into the box's code at the element's path only when the code still has those words; new content for the page waits until the editing ends, `frame.swap`), *Fix it by hand*, *Add a box below… / beside…* (`insert`, then the task box on the new box: `fresh`, placed by the box it came from), *Delete this box…* (confirmed in the menu; `delete`), *Open … in the full editor*, *Hide tykerf*; the page block has no add or delete; arrow keys and Escape work in it.
- **Hide tykerf** opens the page with `?tykerf=hidden`: the page as a visitor sees it, plus a *Show tykerf* button back (`showTykerf` in `page.ts`). **Alt+Shift+T** goes either way.
- **The update notice** (`watchVersion` in `common.js`): *TYKERF was updated… Restart it* when the server's code changed, or *reload this page* with **Reload** when the browser part changed under an open tab; asked on opening and whenever the tab comes back.
- Tests: `test/shell*.test.ts`.

## The full editor

The expert way, beside tasks, for long manual work: the shell's *Full editor* mode (on the box being fixed, when there is one), from its bar, its right-click menu and the quick fix's *More*. Its header holds only what belongs to editing: the brand, the path of the selection, Dim/Blur, Undo/Redo, Compact and × (`.closebtn`: back to Tasks, `go(SHELL)`); the pages, the site, export, Kaity's status and Hide tykerf are the shell's. In the shell's frame (`EMBEDDED`) it moves the top window (`go`). Opened at the top level, `?tykerf=full-frame` is the full editor on its own (its tests use it). `public/` holds plain ES modules, served as they are:

| File | What it holds |
|---|---|
| `tykerf.js` | The panel: state (`S`), the tree, the tabs (Blocks, Text, Code, Size & look, Page), editing text and images in place, tasks on the page (pins, the task form), popovers, refreshes |
| `inline.js` | Pure helpers for editing in place (mapping an element to its box code, cleaning what the browser typed); tested in `test/inline.test.ts` |
| `shell.html`, `shell/` | The shell (above) |
| `fonts/`, `brand/`, `i18n/` | IBM Plex (bundled, SIL OFL), the logo, translations |

How the client works:
- **API base.** `tykerf.js` derives it from `location.pathname`, so the same client works under any `/<page>/`. A page that moved is followed in the shell's Full editor mode (`full()`); a tidied address keeps `?tykerf=full-frame` (`FULL_HERE`), so a reload stays.
- **Per-block state.** Each block keeps its own tab and unsaved drafts (`per(id)`).
- **A page being made.** On load and on the `job` event, `renderJob` shows a modal over the page with the job's steps: the importer's stages (`onStep`, English sentences translated with `t()`), or the AI's tool calls. It has an × (stop) and, at the end, a short guide with *Open the editor* / *See the page*. The modal blocks the page, so nothing disturbs the AI.
- **How the job modal looks.** While it shows, the panel and the Edit button are hidden; the TYKERF logo and the × head it, with Kaity's line under them, smaller. Steps come short from `step()` in `ai.ts` and wrap, never clipped (Chrome garbles clipped lines in that scrolled list). A running job is a small card in the bottom right corner over a light veil (`.jobmodal.running`), so the page coming together is what people watch; at the end it returns to the middle.
- **A page coming into focus.** While Kaity builds a page, `state().build` lists the boxes with sample content left (`leftovers`), apart in `strong` (not reached yet) and `soft` (changed since the last whole-page step: `Workspace.boxesWorkedOn`). `applyFocus()` writes them as blur rules in a `<style id="tykerf-focus">` in the page's head; `refocus()` applies new rules a frame after the body is replaced, so a finished box sharpens with its transition. *See the page clearly* turns it off; the end of the job clears it.
- **Refreshes.** A `changed` event reloads the state and the page's body. A change of head reloads the whole page, because a head can't be swapped in place. Refreshes wait while text is being edited or the image tool is open.
- **Text.** Every string a person sees goes through `t('English text', vars)`, with whole sentences as keys (see [Extending TYKERF](extending.md#a-translation)).
- **Fonts.** The panel's fonts are declared in `document.head` under TYKERF-only names (`@font-face` doesn't work inside a shadow root) and served by TYKERF. Nothing loads from a CDN.

### Tasks and Kaity in the full editor

Kaity is asked with tasks here too (it has no Kaity tab). Open tasks show as pins; the context menu's *Add a task for Kaity here…* (`openTaskForm`) and the empty Text tab's *Leave a task for Kaity* write an ordinary task, and *Add and give it to Kaity* / a pin's *Give it to Kaity* start the task run with it (`/taskrun/start`) and take the top window to Tasks, where she is followed. While she works, her block carries her balls in the tree and a frame on the page (`drawKaity`). The block conversations' endpoints (`/_tykerf/ask`, `/_tykerf/chat/reset`, `/_tykerf/tasks/ask`) stay on the server, unused by the interface.

### Editing in place

`tykerf.js` does the editing, with the pure helpers in `public/inline.js`.
- **Mapping.** An edit maps a page element to the box code by its element path (skipping `style`/`script`/`template`), and only when the code there has the same markup as the element had when the edit started. Otherwise it falls back to the Text tab.
- **Shared blocks.** A box that shows one is mapped against its code as the page shows it (the block, its slots filled), and saved through `setContent`, which splits it (`Workspace.sharedEdit`): what is inside the block's `data-slot` elements is this page's (its own file's `<template data-slot>`), the rest the block's, every page's. So editing a slotted heading in place fills the slot, and the block stays as it is. The Text tab of such a box lists its slots instead (`renderSlots`, `POST /_tykerf/slots` → `Workspace.setSlots`), each with the block's text as its placeholder.
- **Add files…** (the Page tab's *Files*, `POST /_tykerf/files`; the manager's head code card, `POST /_tykerf/site/files`, and Media, `POST /_tykerf/site/media/upload`): one file per request, base64 in JSON (the body limit is 36 MB), into `files.ts` `addFile`, which answers the address to write.
- **Size & look** also lists the site kit's styles for a class (*Class styles*, `S.kit.classes` from `GET /_tykerf/kit`): one toggles the tag `k-<name>` on the block (the `tag` op accepts it when the class style exists), which renders as the class `k-<name>`. The Code tab lists them, `class="k-<name>"`, to copy.
- **Text** edits are limited to inline-only elements (text, `br`, `strong/b/em/i/a`). `cleanInline` keeps the elements that existed before the edit as they were, and allows only `strong`, `em`, `a[href]` (safe schemes) and `br` from the browser.
- **Images.** Crop, turn and scale happen in a canvas, and the result is uploaded as a new file (`POST /_tykerf/asset`, `src/assets.ts`: magic-byte check, raster only, content-hash names, never overwritten). The code changes only `src`, `alt`, `width`/`height`, and drops `srcset`/`sizes`/`<source>`.
- **Where an image came from.** Each derived image is recorded in `.images.json` (`recordEdit`/`imageOrigin`: the original, the crop in the original's turned pixels, quarter turns, the size limit), so the tool reopens the original with the crop on it. Uploads are kept as the original before cropping.
- **Unused files** (`unusedAssets`/`trashUnusedAssets`: nothing in the boxes, head, history, redo list or paste buffer names them; an edited image keeps its original) are offered in the Page tab and move to the page's `.trash/` (`GET /_tykerf/assets/unused`, `POST /_tykerf/assets/clean`). Exports include only the files some page names.

### The Page tab and the corner

- **The corner dock** (`.dock`): *Edit with TYKERF*, a pill that turns solid teal on hover and stays teal while the panel is open; in the shell it shows only while a job keeps the panel closed.
- **Page tab** of the top block: a status line saying where the page's look comes from (inherited, inherited with own values, own theme, own look); in a site, an *Every page / This page only* switch; the theme values (each marked *site* or *this page* in page mode); the page's head code.
- **Presets** rebuild the whole theme block from TYKERF's current theme (`theme` in `/_tykerf/library`) with the preset's values, which updates older heads and repairs damaged band rules. Changing single values only touches `:root`.
