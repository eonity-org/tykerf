# TYKERF 0.2 finish: page names, easy links, AI runners, Desktop extension, exporter

## Context
TYKERF should stay a page editor where AI edits safely block by block, not become a CMS. The user picked four things to finish:
1. page name management;
2. creating links easily;
3. AI integration: an Anthropic-compatible API runner (Anthropic or the user's z.ai proxy), a Gemini runner, and the Claude Desktop extension;
4. an exporter: a static folder, plus a zip download from the editor.

The bigger site manager (sections, media library, shared head, menu) is deferred. Its plan is kept.

**Step 0, once plan mode is off:** save this plan as `docs/plans/0.2-finish.md` and the deferred one as `docs/plans/site-manager.md`, and point to both from `ROADMAP.md`.

Nothing is committed until the user says so. Phases are in order, and each one can ship on its own with its docs and tests.

**Conventions throughout:**
- every UI string goes through `t()` as a whole sentence;
- moves go through `mutate()`;
- read-modify-write goes in `ws.transaction`;
- nothing is loaded from a CDN;
- `CLAUDE.md` and the user guide are updated with each phase.

## Phase 1: page names and links between pages
**Convention:** a link between pages is root-absolute, `/<page>/`, optionally with a `#anchor`. It works as written in the editor, where the site root is `/`, and the exporter (Phase 2) makes it relative.

**`src/site.ts`:**
- `renamePage(dir, from, to)`: `pageNameError(dir, to)`, then `renameSync` the folder (history, `.tykerf/` chats and assets move with it), then `rewriteLinks(dir, from, to)`.
- `rewriteLinks` rewrites `href` attributes equal to `/from`, `/from/` or starting with `/from/` or `/from#`:
  - in every page's boxes, through `ws.setContent(id, html, 'user')`;
  - in every page's head, through `ws.setHead`;
  - each page inside its own `ws.transaction`;
  - in one `ws.group('links follow page <from> → <to>')` per page.
- `removePage(dir, name)` moves the folder to `<site>/.trash/<name>-<timestamp>/`. Nothing is deleted.
- `pageLinks(dir)` lists every root-absolute `href` per page and box, and marks the ones that match no page. Rename and remove use it to say how many links changed or will break.

**Editor:**
- **`src/editor/server.ts`:**
  - `POST /_tykerf/site/rename {from,to}` and `POST /_tykerf/site/remove {name}`, site mode only, behind `foreign()`.
  - Both are refused while any page's AI is running ("an AI is working on "<page>"; wait for it to finish"). The links of every page are rewritten, and the AI's MCP child process writes the same folders.
  - Before renaming, `hosts.get(from)?.close()` and delete it from the map.
- **`src/editor/page.ts`:**
  - New `PageHost.close(movedTo?)`: unsubscribe the store watcher (keep the function `store.watch` returns), send SSE `moved {url}` and end the SSE clients.
  - New `PageHost.refresh()` broadcasts `changed`. The server calls it on every other host after a rename, because their links changed on disk through other `Workspace` objects (folder watchers also catch it; this is the sure path).
- **`tykerf.js`:**
  - **Page switcher popover:** the current page gets **Rename this page…** (popover with a name field; it shows the error from the server) and **Remove this page…** (confirm popover: "N links to it from other pages will break; the page is kept in .trash").
  - **SSE `moved`:** `location.replace(url)`.
  - **Link popover** (`linkPrompt`, ~line 1717): in a site, a list of the site's pages under the address field. Clicking one fills `/<page>/`; the current page is marked. The placeholder becomes `https://…  #section  /page/`. `safeHref` already allows root-relative paths; verify.
  - **The Text tab's link editing** (`editable parts`, ~line 870) gets the same page list through a `<datalist>`.

**Tests:**
- `test/site.test.ts` (new):
  - a rename rewrites the links in another page's boxes and head, and leaves `/fromage/` alone;
  - the rename shows in each page's history as one step;
  - name refusals;
  - remove goes to `.trash`;
  - `pageLinks` finds broken links.
- `test/editor.test.ts`:
  - the rename endpoint, then the old URL gives 404 and the new one serves;
  - refused while an AI runs (fake runner);
  - the SSE `moved` event;
  - `foreign()` on both endpoints.

## Phase 2: the exporter
**`src/export.ts` (new):**
- `exportSite(dir, outDir)` / `exportPage(ws, outDir, path = '')` writes:
  - each page as `<out>/<page>/index.html` (a single page: `<out>/index.html`), through `ws.page({ title })`, with no TYKERF script;
  - the page's `assets/` copied next to it.
- **Address rewriting:**
  - root-absolute addresses (`/page/…`, `/assets/…`) in `href`, `src`, `srcset`, `poster` and CSS `url()` become relative to the page's depth (`../about/`). The export then works from any host, a sub-path, or a file opened from disk.
  - Links between pages point at `…/index.html` when `--file` is given; by default they keep the directory form.
- Nothing from `.tykerf/`, the history, `.images.json` or `types/` goes into the export.
- **A report:**
  - broken internal links;
  - images, fonts and stylesheets still loaded from other servers (common after an import);
  - the total size.

  The CLI prints it, and the editor shows it as a toast.
- **Zip:** `zip(files: {path, bytes}[]): Uint8Array` in `src/zip.ts`, about 60 lines: local headers plus the central directory, deflate through `zlib.deflateRawSync`, `zlib.crc32` (Node ≥ 22.2, and `engines` already says ≥ 22). No new dependency.
- **CLI:** `npm run cli -- export <dir> <out-dir> [--zip] [--file]`. The `render` command stays as it is.
- **Editor:**
  - `GET /_tykerf/export.zip`: the whole site, or the page in single-page mode. It is a GET with no state change, so `foreign()`'s host check applies.
  - It answers with a `content-disposition` attachment named `<site>-<date>.zip` and an `x-tykerf-report` header (JSON, short).
  - **Export site** in the page switcher popover, **Export page** in the root's Page tab.

**Tests:** `test/export.test.ts`:
- two pages with links both ways, an asset and a nested anchor;
- the folder has the expected files, relative links resolve on disk, there is no `_tykerf` reference, and the report lists a remote image;
- the zip round-trips: read back with a small unzip in the test, using `zlib.inflateRawSync`;
- Playwright opens the exported `index.html` from `file://` and follows a link.

## Phase 3: the runner refactor and the Anthropic-compatible API runner
**MCP tools as a factory (no behaviour change):**
- Move the body of `src/mcp/server.ts` into `src/mcp/tools.ts`: `createTykerfServer(ws: Workspace, opts: { scope?: string }): McpServer`. Module globals (`ws`, `runScope`, `server`) become closure state.
- `server.ts` keeps only the argument parsing and `connect(new StdioServerTransport())`. `screenshot`/`evaluate` import Playwright lazily, which Phase 5 needs anyway.
- The existing MCP tests must pass unchanged.

**In-process tools for API runners:**
- `src/editor/tools-client.ts`: `openTools(ws, scope)` builds `createTykerfServer(new Workspace(ws.store), { scope })`. It is a separate `Workspace` object, so the editor's `lockBlock` guard (per object) doesn't refuse the AI's own changes; the store lock still serialises writes.
- It links it to an MCP `Client` with `InMemoryTransport.createLinkedPair()` (in the SDK as `@modelcontextprotocol/sdk/inMemory.js`).
- It returns `{ tools: listTools(), call(name,args) }`. The scope, refusals and history labels are therefore exactly the ones Claude Code gets.

**`ApiRunner` (`src/editor/runners/anthropic.ts`)** implements `Runner`, using `@anthropic-ai/sdk` (a new dependency; it honours `baseURL`):
- The loop: send the system prompt, history and user message (text and images), plus the tools converted from the MCP list (`name`, `description`, `input_schema`).
  - While the reply has `tool_use` blocks: `on.step(step(name,input))`, call each tool, and send back a `tool_result` (with `is_error`).
  - An MCP image result becomes an image block, so screenshots work.
  - The final text goes to `on.answer`.
- Caps: 40 tool calls per request (then "stopped after 40 steps; ask again to continue"), `max_tokens` 8192, `AbortController` for `cancel()`.
- **Conversation memory:** the API messages are kept in `.tykerf/chats/<id>.api.json` as `{ runner, model, messages }`.
  - Screenshots older than the last turn are replaced by the text `[screenshot]` so the file and the context stay small.
  - Older turns are dropped past ~100k characters.
  - `RunRequest.session` holds `api:<runner>`. Switching runners starts a fresh model context (the visible chat stays), and `AI.reset` removes the file too.
- **Errors:**
  - 401/403 → "the API key was refused (check TYKERF_API_KEY / ANTHROPIC_API_KEY)";
  - 429 → "the API is rate-limited; try again in a moment";
  - network errors → "could not reach <base URL>".

**Configuration:**
- `.env` at the editor's working directory or the site folder, loaded with `process.loadEnvFile` when present, and never sent to the browser.
- `TYKERF_RUNNER=claude-code|anthropic|gemini` (default `claude-code`). `TYKERF_MODEL` (default per runner, e.g. `claude-sonnet-5-5`).
- `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` (sent as a bearer token, the form z.ai's Anthropic-compatible endpoint uses), plus `ANTHROPIC_BASE_URL`.
- Add `.env.example`, and make sure `.env` is in `.gitignore`.
- `ClaudeCodeRunner` passes the environment through, so Claude Code with the z.ai base URL also works. Say so in the docs.
- `state().aiRunner = { runner, model }`, so the AI tab shows which model answers.

**Tests:**
- A fake Anthropic server: a local HTTP server pointed at by `ANTHROPIC_BASE_URL`, which answers with scripted `tool_use` turns. It checks that:
  - the tools run in scope, and a change outside the scope comes back as `is_error`;
  - the steps and the answer reach the chat;
  - cancel aborts;
  - the history file is trimmed;
  - a 401 gives the friendly message.
- `test/mcp.test.ts`: the factory still has the same tools.

## Phase 4: the Gemini runner
- `src/editor/runners/gemini.ts` uses the same loop shape over `@google/genai` (a new dependency), with `GEMINI_API_KEY`, optional `GEMINI_BASE_URL`, and `TYKERF_MODEL` (default a current Gemini Pro model, picked at implementation time).
- Tools become `functionDeclarations`. A `geminiSchema()` sanitiser drops `$schema`, `additionalProperties` and unsupported formats from the zod-generated JSON schema; it is unit-tested on every TYKERF tool.
- Tool results go back as `functionResponse`. A screenshot image goes as an `inlineData` part in the same user turn.
- Memory, caps, cancel and error mapping are shared with Phase 3 through a small `runners/loop.ts`. Only the wire format differs.
- **Tests:** a fake Gemini server, with the same cases as Phase 3.

## Phase 5: the Claude Desktop extension (`.mcpb`)
**What it is:** a bundle Claude Desktop installs in one click. It runs TYKERF's MCP server on the user's machine, and Claude Desktop does the thinking with the user's Claude account. No API key or proxy is involved.

**Build:**
- `npm run build:mcpb` uses esbuild (a dev dependency) to bundle `src/mcp/server.ts` into `dist/mcpb/server/index.js`. Playwright stays external and is loaded lazily: `screenshot`/`evaluate` answer "install Chromium for screenshots: npx playwright install chromium" when it's missing, and every other tool works.
- It writes `dist/mcpb/manifest.json`:
  - `server.type: node`, `entry_point server/index.js`;
  - `user_config.page_folder` of type `directory` → `--dir ${user_config.page_folder}`;
  - the tool list generated from `createTykerfServer`;
  - an icon from `BRAND.md`.
- Then `npx @anthropic-ai/mcpb pack dist/mcpb tykerf.mcpb`. Check the current manifest version and fields against the mcpb docs at implementation time.

**Release:** a GitHub Actions job attaches `tykerf.mcpb` to each release. Don't create it until the user agrees to push.

**Tests:**
- The built bundle starts over stdio in a test.
- `listTools` matches the factory.
- `get_layout` works on `examples/widgets`.
- `mcpb validate` passes on the manifest.

**Docs:** a user-guide page `docs/user-guide/en/claude-desktop.md` (install, choose the page folder, what it can and can't do, scope with `.scope`/`focus`), and a pointer in `README.md`.
