# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TYKERF lets people and AIs identify, track and change the blocks of a web page. Pages are **slicing trees** in postfix (Polish expression) notation, the way slicing floorplans are written in IC design (Wong & Liu, 1986); the formal definition is `docs/slicing-notation.md` (keep it in sync with the code). An AI edits pages through validated tree moves exposed as MCP tools instead of rewriting HTML/CSS. The editor (`src/editor/`) puts a panel over the real page for people, with an AI conversation per block. TYKERF is an eonity project, Apache-2.0; cite the published literature (Otten, Wong & Liu, Stockmeyer, Nagy & Seth).

## Commands

```bash
npm test                                   # vitest: notation, moves (incl. 1000-sequence property test), shape functions, boxes
npx vitest run test/moves.test.ts -t swap  # single file / single test

npm start -- examples/widgets [--port 4400] [--host <addr>]   # the editor (edits the workspace in place)
npm start -- my-site [--layout t --theme th]  # a new/empty folder is a site: start screen, pages at /<page>/
npm run cli -- outline "1 2 V 3 H"         # parse + outline;  also: normalize "<postfix>"
npm run cli -- layouts                     # list page layouts, components and theme presets
npm run cli -- new <dir> [layout] [--theme <name>]   # create a page from a library layout
npm run cli -- render examples/widgets     # -> examples/widgets/out/index.html
npm run cli -- optimize examples/widgets 1440 [--write]
npm run cli -- import <url> <dir> [--structure-only]          # website -> workspace (XY-cut importer)
npm run cli -- export <page-or-site> <out-dir|out.zip> [--files]   # plain files for any web host
npm run metrics -- <page.html> [--widths 375,768,1440] [--shots dir]   # Playwright scores + screenshots
npm run mcp -- --dir examples/widgets      # MCP stdio server
npm run build:mcpb                         # Claude Desktop extension: dist/mcpb/ + dist/tykerf.mcpb (scripts/build-mcpb.ts)
npm run build:plugin                       # Claude plugin for Anthropic's directory: dist/plugin/ (scripts/build-plugin.ts, sources in plugin/)
```

Playwright needs Chromium (`npx playwright install chromium`).

The editor's AI is configured in `.env` (see `.env.example`): `TYKERF_RUNNER` (`claude-code` default, `anthropic`, `gemini`), `TYKERF_MODEL`, `TYKERF_API_KEY`/`TYKERF_AUTH_TOKEN`/`TYKERF_API_BASE_URL` (falling back to `ANTHROPIC_*`), `GEMINI_API_KEY`. `server.ts` loads `.env` from the working folder and the page/site folder unless `TYKERF_DOTENV=off` (the tests set it, so a developer's `.env` doesn't change what they check). `TYKERF_TURN_TIMEOUT` (seconds, default 180) limits one model turn for the API runners. `TYKERF_DIR` is the MCP server's default `--dir`.

## Architecture

The data flows one way: **postfix text → `Layout` tree → moves → render/evaluate**.

- `src/model.ts`: `Layout = { root: Node, overlays: Overlay[], rules?: Rule[] }`; `validate()` is the single source of structural truth.
  - Nodes are `Leaf | Empty | Op`. Op kinds: `H` (cut → children stacked = flex column), `V` (side by side = flex row), `W` (pinwheel, 5 children), `P` (periphery, 5 slots in **reading order N W C E S**, `_` = empty). H/V are n-ary.
  - **Responsive rules** (`rule <id> below=<px> flip|hide <target>` / `ratios <target> a:b`) apply while viewport width < below; the smallest `below` wins. `effective(layout, W)` returns the tree as it is at width W. Both the shape model and the renderer's media queries derive from it, so keep all rule semantics inside `effective()`.
- `src/notation.ts`: tokenizer/parser/serializer. Leaf attrs in `[...]`, op attrs in `{...}`, op id after `@`, H/V arity as a suffix (`V3`). `normalize` merges same-operator chains. The `.slice` file format writes every op id (auto ids `o<n>` count as unnamed) plus `overlay …` and `rule …` lines.
- `src/refs.ts`: references. `resolveRef` accepts a name (`faq`), a path (`page/row2/faq`, `row2/2` = 2nd child) or a position (`#4.2`). The MCP server resolves every node argument through it, so the history logs resolved names.
- `src/types.ts`: box types, `types/<type>.json` per workspace (`within`, `notWithin`, `children`, `max`, `content.tags/scripts/styles`, `template`). Enforced in `Workspace.save`/`rename` (a change may not *introduce* violations) and `Workspace.setContent`. Untyped blocks are unchecked.
- `src/scope.ts`: the AI may only change the scope block. `scopeViolation` compares `outsideSignature` (the tree with the scope as a placeholder, plus rules/overlays targeting outside) before and after a change. The scope lives in the workspace `.scope` file (`<id> <author>`), or for an editor AI run in the MCP server's `--scope <id>` (that process only, follows the AI's renames; the editor's `AI` class follows them too through `Workspace.followRenames`, moving the block's chat and lock); the AI cannot change or remove a user scope, and a user scope whose block is gone refuses every tool (never lifts the limit). `insideSignature` is the counterpart, used to lock the AI's block for the editor.
- `src/check.ts`: `leftovers(ws, { within })`, what a block has left unfinished (components' sample text less `KEEP`, placeholder pictures, links without a target). MCP `check_page`; `AI.ask` reports only what a request added (a snapshot at the start) and gives whole-page builds one automatic fix pass; *Fix them* / *Leave them* (`.tykerf/kept.json`). Keep `KEEP` to interface words: anything else from a component's sample text counts as unfinished.
- `src/moves.ts`: every move is pure (`clone → mutate → finish`). `finish` drops overlays and rules whose target vanished, then re-validates, so a move either returns a valid layout or throws. New moves must go through `mutate()`. `insertNext` is the editor's add beside/below.
- `src/shape.ts`: shape functions (height as a function of width) for `text`/`image`/`fixed` leaves. V = max of children, H = sum, P/W through grid tracks. Cost = height + wasted area + penalties. `optimize()` runs coordinate descent over ratios and leaf variants. `LEAF_PAD` and the font constants are shared with `render.ts`.
- `src/render.ts`: tree → standalone HTML. DOM order = tree order. H/V become flexbox; P/W CSS grid areas (CSS strings in inline styles must use **single quotes**); overlays use CSS anchor positioning.
  - `minw` is an optimizer hint, not rendered. `minh` renders as `min-height`; in a column a child with `minh` gets `flex:<w> 0 auto` (an explicit min-height replaces the flex item's content minimum).
  - `maxw` renders as `max-width` + centered.
  - `scopeStyles()` wraps each box's `<style>` in `@scope ([data-sw="<id>"])`. The default box look uses `:where()` so box CSS always wins; base rules that reach inside boxes must be `:where()` too.
- `src/store.ts`: where a page's files live. `Store` is synchronous with relative `/` paths (`read`/`readBytes`/`write`/`append`/`remove`/`exists`/`list`, optional `watch`); `checkPath` refuses absolute paths and `..`. Optional `lock(fn)` (FolderStore: a `.tykerf.lock` folder, reentrant, stale after 5 s) keeps a read-modify-write whole across processes (the editor and the AI's MCP child change the same folder). `FolderStore` (disk) and `MemoryStore` (tests, previews; `external()` simulates outside changes). A remote store keeps a local snapshot and syncs outside these calls. **Nothing in the core, the MCP server or the editor reads page files directly**: they go through `Workspace` or `ws.store` (box types, AI chats and images, the buffer, imports too).
- `src/workspace.ts`: `new Workspace(dirOrStore)`; a page with `layout.slice`, `boxes/<id>.html`, optional `types/` and `head.html`, `.history.jsonl` (undo + audit log) and `out/`.
  - Always go through `Workspace.contents()`/`setContent()`; never read box files directly. `ws.dir` and the `*Path` getters exist only for folder workspaces (the CLI, the AI's MCP child process). Always render with `Workspace.page()`.
  - **Every read-modify-write goes in `ws.transaction(fn)`** (the store lock): the MCP tool handlers and the editor endpoints wrap load → move → save in it. Keep it synchronous and short; slow work (optimize, screenshots) runs outside and re-checks the layout inside.
  - `addGuard(fn)` lets a caller refuse changes made through that `Workspace` object (`Change`: layout prev/next, content id, head); the editor uses it to lock the AI's block during a run.
  - `content(id)` reads only that box; `boxIds()` lists boxes with code without reading them. Use them instead of `contents()` when you need one box or only the names.
  - History entries record `label`, `author` (`ai` from MCP, `user` from the editor), `at` and the previous state. `Workspace.group(label, author, fn)` makes several changes one undo step; if `fn` throws, what it did is undone, and a nested group is part of the outer one. The history keeps the last 200 steps (trimmed at 250, on step boundaries); older entries go to `.history-archive.jsonl` without their snapshots. `undo()` pushes the step and the state it replaced onto `.redo.jsonl`; `redo()` re-applies it and puts the entry back on the history; `log()` (every new change) clears the redo list. `peekUndo`/`peekRedo` let callers scope-check before acting.
- `src/mcp/tools.ts` + `server.ts`: `createTykerfServer(ws, { scope })` builds every tool (server.ts is only the stdio entry with `--dir`/`--scope`; the editor's API runners use the same factory in-process). Each tool call loads the workspace, applies a move, saves, and replies with only the outline lines that changed. `edit_content` replaces one exact piece of a box's code (unique unless `all`), so a model doesn't rewrite a long box (copies carry ~40 KB of CSS) for a small change. `commit()` checks the scope before saving. `add_picture` is the model's only way to add an image (an SVG it draws, or a picture attached to the request); `set_content`/`edit_content` warn about files the page doesn't have, so a model doesn't loop on made-up file names.
  - **Pages:** with `home` (the stdio server's `--dir`), `list_pages`/`open_page`/`new_page` work on the pages of a site and reassign the server's `ws`; every tool reads `ws` when it runs, so never copy it at startup. Refused under a run scope.
  - **Folders:** `server.ts --lazy` (the Claude plugin) starts with no folder open (`createTykerfServer(null, { folders })`): only `open_folder` and the library lists answer until `open_folder` opens a page, a site or an empty folder, the default (`--dir`, else `TYKERF_DIR`, else `~/TYKERF`) without a path. Never give `folders` to the extension or the editor's runs.
  - **The AI-facing vocabulary is `row`/`column`/`wheel`/`periphery`** (`KIND_WORD`), never H/V; postfix is not shown to the model.
  - `screenshot` (`src/screenshot.ts`) returns an MCP image of a block (dashed frame, 24 px context) or the page at a width; `evaluate` uses `src/metrics.ts`.
- **Claude Desktop extension** (`scripts/build-mcpb.ts`, tested in `test/mcpb.test.ts`): esbuild bundles `src/mcp/server.ts` into `server/index.js`, with `library/` beside it (library.ts finds `../layouts`) and `playwright`/`playwright-core` in `server/node_modules` (external; `screenshot.ts`'s `launchChromium` imports it lazily, so the server runs without Chromium). The manifest (v0.3, `user_config.page_folder` → `--dir`) lists the tools from `createTykerfServer`; `mcpb validate` and `pack` run in the build. Keep module-level side effects out of code the server imports (metrics.ts's command guard checks the file name).
- **Claude plugin** (`scripts/build-plugin.ts`, tested in `test/plugin.test.ts`; plan `docs/plans/claude-plugin.md`): the extension's bundle (`bundleServer`) plus `plugin/` (README with the privacy policy), a `plugin.json` and `.mcp.json` starting the server with `--lazy`, and Playwright from a lockfile. Releases commit it to the `claude-plugin` branch, which Anthropic's directory follows. The skill (`plugin/skills/tykerf/SKILL.md`) may name only existing tools (tested): update it when a tool is renamed or its use changes. Keep it inside the directory's file rules the test checks, and `page_folder`'s default empty (Cowork drops a server whose setting has none).
- `src/site.ts`: a **site** is a folder whose subfolders are pages (`siteKind(dir)`: `page` when it has `layout.slice`, `site` when empty/new or its subfolders are pages, else an error; page names `^[a-z0-9][a-z0-9-]*$`, not `_tykerf`/`assets`/`out`).
  - **Shared theme:** the site's own `head.html` (fonts in the site's `assets/`, `url("/assets/…")`) renders before each page's head: `new Workspace(dir, { site })` (`pageWorkspace`, `siteOf` for the MCP server and CLI) and `ws.siteHead()`. A head with `NO_SITE_HEAD` (imported copies) keeps its own look. The site head has its own undo (`setSiteHead`/`undoSiteHead`, `.tykerf/site-head.jsonl`).
  - A page's own values over the site theme go in `<style data-tykerf-override>` (`readOverrides`/`withOverrides`, only values that differ). `setTheme` follows `themeTarget`: one page's AI never restyles the other pages.
  - Links between pages are root-absolute (`/about/`); `renamePage` + `rewriteLinks` rewrite `href`s in every page (one undo group per page); `removePage` moves the folder to `.trash/`. `/_tykerf/site/{rename,remove}` refuse while any page's AI runs and close the page's host (`PageHost.close` sends SSE `moved`; `refresh` reloads the others).
  - Details (the four look states, `newPageLike`, `shareTheme`): `docs/developer-guide/en/architecture.md#sites`.
- `src/editor/`: the editor.
  - `server.ts` routes: a page folder is served at `/` (one page host); a site serves each page at `/<page>/` (a host per page, made on first use) and `/` serves `public/start.html`, the site's home (its pages to open, rename and remove, and the chooser for a new one; on a new site only the chooser). Global endpoints: `/_tykerf/library` (layouts + theme presets), `/_tykerf/preview/<layout>/<theme>/` (rendered in a `MemoryStore`, sandboxed), `/_tykerf/site`, `POST /_tykerf/site/new`. TYKERF's own files (`tykerf.js`, `inline.js`, `chooser.js/css`, fonts, i18n) are served at `/_tykerf/…` and under each page. Pages load `_tykerf/tykerf.js` relatively, and `tykerf.js` derives its API base from `location.pathname`, so the same client works at `/` and `/<page>/`.
  - **The chooser** (`public/chooser.js`, start screen and New page…): *Show or describe it*, *Like this page*, *A layout*, *A copy of a website*, all through `POST /_tykerf/site/new`. An AI build or a copy runs as the page's **job** (`PageHost.job`, SSE `job`, `renderJob` in tykerf.js as a modal over the page); a stopped copy goes to `.trash/`. Flow and endpoints: `docs/developer-guide/en/ai-and-mcp.md#the-ai-first-start` and `editor.md`.
  - **The site manager** (`public/start.html`) is at `/_tykerf/site/`; `/` redirects to the home page in `site.json` (`readSite`/`setHome`/`setTitle`/`pageTitle` in site.ts) or shows the manager. `/pages/` = `siteIndex`, `/sitemap.xml` = `siteMap`. *Styles & scripts* edits `siteCode`/`setSiteCode`: the site head without its theme and fonts blocks (`KEPT`), which it never changes.
  - **Kaity for the whole site:** `siteAI` in server.ts is an `AI` with `{ site: dir }` (one `SITE_CHAT` conversation, `siteSystem()`, no block lock or leftovers check); its runs pass `RunRequest.home`, so the MCP tools include `list_pages`/`open_page`/`new_page` and no scope. Page runs and the site run refuse each other (409).
  - **Serving to visitors** (`auth.ts`): with `TYKERF_ADMIN_PASSWORD`, `visitorMay()` in server.ts lets visitors load pages (no editor script: `createPageHost`'s `admin`), assets, `/`, `/pages/`, the sitemap, sign-in and its fonts; everything else needs the session cookie. Keep every new editor address under `/_tykerf/`, so it stays closed to visitors.
  - **The Site menu** (the icon between the logo and the page name, `openSiteMenu` in tykerf.js) holds only what acts on the whole site or on TYKERF itself and can't be done from a page: export (`/_tykerf/export/report`, then `/_tykerf/export.zip`; `?page=<name>` for *Export this page…*), AI status (`/_tykerf/ai/status`, `POST /_tykerf/ai/test` → `Runner.status()`/`check()`), and *Manage the site…* (what's built and what's left: `docs/plans/site-manager.md`). Keep it to whole-site and TYKERF-wide actions; a page's own theme and head stay in its Page tab. The page list (the page name next to it) stays the quick way to switch, rename and remove the current page, and to add one (New page…).
  - `page.ts`: `createPageHost(ws, { name, site })`: everything one page needs (its `AI`, SSE clients, watcher, buffer, `OPS`, `state()`, the `/_tykerf/` API and its `assets/`), given paths relative to the page. Named ops (`insert`/`add`/`flip`/`ungroup`/`reorder`/`ratios`/`height`/`width` (maxw)/`rename`/`delete`/`remove`/`paste`/`drop`). Delete moves a block's code into the previous box; Remove puts it in `.tykerf/buffer.json`. Workspace changes are pushed to the page over SSE.
  - **Restart notice:** `GET /_tykerf/version` compares `codeStamp()` (src/**/*.ts at startup) with now; the client shows *TYKERF was updated…* when outdated or when the address 404s (an older server). New client features that need new server routes are covered by it.
  - **Security:** listens on 127.0.0.1 by default; `foreign()` refuses other Host headers, and changes from other origins or without a JSON body. Keep every state-changing endpoint behind it. Box scripts run in the editor's page and origin, so they can call the API too (outside the AI scope); that is a documented, accepted risk (SECURITY.md), not something `foreign()` stops.
  - Undo/redo are refused (409) while the AI runs.
  - **Kaity** is the name people see for the editor's AI (Tydal's is Aity; see BRAND.md): every UI string and server message says Kaity, the system prompt names it, and `kaityMark()` in tykerf.js draws eonity's three-ball isotype, pulsing while it works. Code keeps "AI" (`ai.ts`, runners, CSS classes `.msg.ai`). `ClaudeCodeRunner.warm()` finds out in the background whether `claude` is installed; never call the CLI synchronously from a request. Every `claude` it starts gets `claudeEnv()` (the environment without `CMUX_*`: a cmux terminal's wrapper would otherwise take Kaity's runs as its own sessions).
  - `ai.ts`: one AI conversation per block in `.tykerf/chats/<id>.json`. The `AI` class keeps chats, the scope and the block lock; a `Runner` (`runners/index.ts`, picked by `TYKERF_RUNNER`) runs the model: `ClaudeCodeRunner` (default; `claude -p … --tools "" --strict-mcp-config --allowedTools mcp__tykerf`, scope via `--scope`), `runners/anthropic.ts` and `runners/gemini.ts`. The API runners share `runners/loop.ts` and run the MCP tools in-process (`tools-client.ts`) on **their own `Workspace` object**, so the editor's block lock doesn't refuse the AI. Tests use a fake runner and fake API servers (`test/runners.test.ts`). Details: `docs/developer-guide/en/ai-and-mcp.md#runners`.
  - **Editing in place** (`tykerf.js` + `public/inline.js`, pure helpers): an edit maps an element to the box code by element path, and only when that code still has the markup the element had; otherwise it falls back to the Text tab. `cleanInline` allows only `strong`, `em`, `a[href]` (safe schemes) and `br` from the browser. Edited images are uploaded as new files (`src/assets.ts`: magic-byte check, raster only, content-hash names, never overwritten). Details: `docs/developer-guide/en/editor.md#editing-in-place`.
  - `public/`: plain browser JS, no build. **Every UI string goes through `t('English text', vars)`** (English is the key; catalogs in `public/i18n/<lang>.json`, served by `/_tykerf/i18n/<lang>.json`, `{}` when missing). Use whole sentences as keys, never concatenated fragments; escape values that go into HTML before passing them. Don't name a local variable `t`. All UI lives in a shadow root. Fonts (IBM Plex, SIL OFL) are bundled in `public/fonts/` and declared in `document.head` under TYKERF-only names (`@font-face` doesn't work inside a shadow root); never load anything from a CDN.
- `src/library.ts` + `library/`: page layouts (`layouts.json`), theme presets (`themes.json`), components (`components/*.html` + `components.json`), the theme (`theme.html`: `:root` variables in `<style data-tykerf-theme>`), bundled fonts and placeholder images. `createPage` writes a page from a layout; `useComponent` fills one box; `useLayout` replaces a page's blocks (MCP `use_component`/`use_layout`/`use_theme`).
  - `withThemeValues` changes only `:root` (the band tones `.t-tone-alt/-soft/-dark` reuse the variable names). `withFonts` copies the fonts a theme names into `assets/`; nothing loads from a CDN.
  - **Components use only theme variables** (tested), paint `var(--section-bg, …)` so any section takes any tone, and must work at any width. After changing a component or a preset, run `test/design.test.ts` (WCAG AA contrast per band, heading order, sideways scroll in every layout of the main presets).
  - User-facing defaults are the `launch` layout and `DEFAULT_THEME` (`studio`); `createPage`'s own default is `BASE_THEME` (`clean`, not offered). Keep the offered set small (9 layouts, 6 presets). Retired items and the `W`/`P` showcase layouts live in `Other_Layouts/` (never loaded; kept valid by a test).
  - The editor serves the page's `assets/` at `/assets/`, and `render()` copies them to `out/assets/`.
- The AI changes the theme only through MCP `get_theme`/`set_theme` (`readTheme`/`setTheme`/`themeValueError` in library.ts): existing variables only, each value checked by kind (colour, length, font list) and refused if it contains `;{}<>\`, comments, `url(` or `@import`; allowed only when the scope is the page root (or none). The rest of head.html stays out of the AI's reach.
- `head.html` changes go through `Workspace.setHead` (history kind `head`, undo/redo); scoped MCP undo/redo refuse them unless the scope is the page root. The editor's Page tab edits it, and a head change reloads open pages (`state().head` is a version number).
- `src/export.ts`: a page or a site as plain files (`exportFiles` → `exportToFolder` / `exportZip`; `src/zip.ts` is a dependency-free ZIP writer). `relativize` makes root-absolute addresses (links between pages, `/…/assets/`) relative to the page's depth (`files: true` → `…/index.html`); a site gets an `index.html` that opens its first page. The report lists broken page links and what still loads from other servers. No TYKERF state goes along. Editor: `GET /_tykerf/export.zip[?links=files]` (report in `x-tykerf-report`), from the Site menu.
- `src/publish.ts`: **Publish** commits `publishFiles` (the export, `.nojekyll`, and `MANIFEST`, the list of files TYKERF wrote) to a GitHub branch through the Git Data API (`publishToGitHub`: blobs only for files whose git blob hash differs, one tree, one commit, the ref moved). It deletes only files on the previous list, so a repository's own files stay. Settings in `site.json` `publish` (`setPublish`, `publishSettingsError`); the token is `TYKERF_GITHUB_TOKEN`, `TYKERF_GITHUB_API` points elsewhere (tests: `test/publish.test.ts` runs a fake GitHub).
- `src/importer.ts`: website → workspace by recursive XY-cut over the rendered DOM (Playwright at 1440 px), with per-box computed styles and `@media` blocks sampled at the site's own breakpoints. One import at a time; http(s) only. `placeSection` grafts one section of a copy into a box (one undo group, plus a `<!-- tykerf-import in-<box> -->` head block). `src/import-files.ts` downloads what the copy loads into `assets/` (checked by bytes) and rewrites the code. Details: `docs/developer-guide/en/architecture.md#the-importer-in-detail`.

## Conventions

- Leaf names may not look like operators (`H`, `V3`, `P`…) and must be unique; leaf id = its name.
- Tests that touch examples read `examples/*/layout.slice`. Keep the examples valid and the `optimize never makes examples worse` test passing.
- Brand rules (colours, mark, type) are in `BRAND.md`. Docs follow the eonity layout (as in FullFrame): `README.md`, `DEPLOY.md`, `ROADMAP.md`, `BRAND.md`, `NOTICE` at the root, the user guide in `docs/user-guide/<lang>/` (start: `why-tykerf.md`, `getting-started.md`) and the developer guide in `docs/developer-guide/<lang>/` (`setup`, `architecture`, `following-a-change`, `editor`, `ai-and-mcp`, `extending`, `building-on-tykerf` (its examples were run; keep them running), `documentation`); English only today, in `en/`. Update the guides when a feature changes what people see or how the code is extended; `docs/developer-guide/en/documentation.md` maps changes to pages and sets the house style (Kaity is "she"; buttons bold, menu items italic). New pages go in their guide's index table, then `npm run docs:nav`. The demo video and its poster are `docs/media/tykerf-builds-lisbon.{mp4,jpg}`.
