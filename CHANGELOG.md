# Changelog

## Unreleased

- **Tools say what they do.** Every MCP tool has a short title ("Replace the page with a layout") and tells the client whether it only reads the page, changes it, or replaces something whole, so Claude Desktop, Claude Code and other clients can show it and ask before the bigger changes.
- **The MCP server can start with no folder** (`--lazy`, for the coming Claude plugin): Claude opens one with the new `open_folder` tool, a page, a site or an empty folder, and without a path the default: `--dir`, else `TYKERF_DIR`, else `~/TYKERF`. The Claude Desktop extension and `claude mcp add --dir` keep opening their folder at once.
- **A Claude plugin** for Claude Code and Cowork: `npm run build:plugin` writes it to `dist/plugin/`, and each release publishes it to the `claude-plugin` branch for Anthropic's directory. It needs Node.js 20 or later on the computer.
- **A demo video and five new guide pages.** The README, *Why TYKERF* and *Getting started* link a video of Kaity building a page about Lisbon (`docs/media/tykerf-builds-lisbon.mp4`), the user guide adds *Getting good results from Kaity* (`asking-kaity.md`) and *When something goes wrong* (`troubleshooting.md`), and the developer guide adds *Following a change* (`following-a-change.md`), *Building on TYKERF* (`building-on-tykerf.md`) and *Writing the docs* (`documentation.md`).

## 0.1.0 (2026-10-23): first public release

TYKERF's first public release, under the Apache License 2.0. [The first milestone](#the-first-milestone) lists the foundations; this list is what came after it.

- **Kerf is now TYKERF** (wordmark *tykerf*), with the TY signature of the eonity family. Pages made with Kerf keep their blocks and boxes; rename `KERF_` settings in `.env` to `TYKERF_`.
- **Copies bring their images and fonts.** Copying a website now downloads its images, fonts and font stylesheets into the page's `assets/` (recognised by their bytes; SVGs only without scripts), so the copy loads nothing from the original servers and its fonts work wherever it's served. What can't be downloaded stays linked and the export lists it. The command line says how many files came along.
- **Copies keep more of the site:** blocks centred with `margin: 0 auto` stay centred at every width, and animations play (their `@keyframes`, with perspective and 3D settings, come along). Copied fonts are named after their family (`font-manrope-….woff2`).
- **Kaity edits part of a box.** A new tool, `edit_content`, replaces one exact piece of a box's code, so a small change to a long box (a copied site's boxes carry tens of KB of CSS) no longer means writing the whole box again. That was slow with Claude and too long for other models.
- With the API runners, a reply cut off at the length limit no longer runs a broken tool call ("expected string, received undefined"): the model is told its reply was cut off and to change the code in smaller pieces.
- **Kaity in a cmux terminal.** An editor started from cmux no longer hands Kaity's runs to cmux's Claude wrapper (its hooks and session tracking slowed runs and could end them with code 143); Kaity's `claude` starts without the terminal's `CMUX_*` variables.
- When a Kaity run is stopped, the chat says *stopped* instead of `claude exited with code 143`; when something outside TYKERF ends Claude Code, it says so.
- **Unused files.** The Page tab lists files in `assets/` that no box, the head, the paste buffer or an undo step uses, and *Move them to the trash* puts them in the page's `.trash/` folder. Exports leave unused files out.
- The roadmap lists the current nine layouts, six presets and 31 components.
- Two tests no longer fail now and then on a busy machine (a section's band in the editor, and copying a website from the start screen): they wait for the page to hear of a change, or to finish reloading, instead of reading it at once.
- **Fixed: typing in a few boxes did nothing** (Kaity for the whole site, renaming a page in the site manager, the address in *Import a section*): their keyboard shortcut cancelled every other key.
- **Kaity's answers keep their formatting:** bold, italics, code, lists and headings show as such in the Kaity tab, the build window and the site manager, instead of `**` and backticks. Her words are escaped first, so nothing else gets through.
- **The site manager's layout.** The actions come first (+ New page, Ask Kaity about the whole site, Styles & scripts), then the pages, which scroll on their own; each shows its address (`/rome/`). Kaity's three balls mark her panel and button, and pulse while she works.
- **Kaity for the whole site.** In the site manager, **Ask Kaity about the whole site** works on every page, like Claude Desktop: she lists the pages, opens each, changes and checks it, with her steps live and **Stop**. While she works, renames, removals and Kaity on a single page wait.
- **Watch the page come into focus.** While Kaity builds a page, the sections she hasn't reached are blurred, the one she's working on softly, and each turns sharp as she finishes it (no sample content left). **See the page clearly** in her window turns it off; with reduced motion, sections sharpen without the animation.
- **An address under a page that isn't there** (`/prague/asdfad`) gets a *not found* page, for visitors too, instead of the sign-in refusal or a bare `not found`; only the editor's own addresses (`/_tykerf/…`) need signing in.
- **Fixed: an address starting with `//` stopped the editor** (`http://localhost:4400//`, or any request a visitor sends). Addresses are now read as paths, a malformed one gets a 400, and doubled slashes go to the clean address.
- **The editor says when it needs a restart.** Its browser part is read fresh from disk, but the server keeps the code it started with; when that code changes (an update, a `git pull`), the editor and the site manager show *"TYKERF was updated while this editor was running…"* instead of leading to addresses the old server doesn't know (`GET /_tykerf/version`).
- **Site settings: a home page and titles.** `site.json` keeps the site's home page (**Make home** in the site manager) and titles set by hand; a page is otherwise titled by its first heading, and its title names the browser tab. The site's address opens the home page; **the manager moves to `/_tykerf/site/`**; `/pages/` lists the pages by title and `/sitemap.xml` (with `TYKERF_PUBLIC_URL`) maps them. Exports open the home page and include `pages/` (and the sitemap).
- **From any page to the site manager:** a **Manage the site** button next to *Edit with TYKERF* (the two look and behave alike; its symbol is three pages, the front one marked in amber like the logo's block in focus), and *Manage the site…* in the Site menu.
- **Publish the site to GitHub.** The site manager's **Publish** commits the exported site to a GitHub repository (a branch, and a folder if you like), so GitHub Pages, Cloudflare Pages or Netlify, connected to that repository once, put it live. One publish is one commit; only changed files are sent, and only files TYKERF published are ever replaced or removed (a `CNAME`, a README or the site's sources stay). An empty repository is started with a README, and big repositories are listed folder by folder. The token is `TYKERF_GITHUB_TOKEN` in `.env`. Publishing waits while Kaity works, so half a change never goes live.
- **The site manager's pages as icons:** each page's actions are icons with their names in a tooltip: make it the home page (a star, filled amber on the home page), rename, **duplicate** (new: a copy next to it, `<name>-copy`, without its history or conversations) and remove.
- **What Kaity is doing, across the site.** The site manager lists every Kaity run (the whole site, and the block she works on in each page), and her balls pulse on those pages; each opens the page on her block. In the page editor, the block she works on carries her balls in the tree, and another block's Kaity tab says where she is, with **Go there**. A page opens on a block and tab with `?block=<name>&tab=<tab>`.
- **Links between pages** in the site manager: broken links first, each opening the page on the box it's in, then the pages no other page links to, then what each page links to.
- **The logo looks right everywhere.** Its wordmark was live text in IBM Plex Sans, so where the font isn't installed (GitHub, image viewers) another typeface took its place and the end of the word was cut off. It is now in outlines, drawn from the bundled font, and its frame starts at 0 with an explicit size (Quick Look ignored a frame starting below 0 and lost the margin). The docs show it with square corners: Markdown viewers that round every image (Markdown Preview on the Mac, 8 px) cut the f's hook off at header size.
- **Every docs page has a header and footer:** the TYKERF logo and where the page sits, and at the end the previous and next pages of its guide, its index and the project's links. `npm run docs:nav` writes them; a test checks they're current and that no link between docs is broken.
- **The user guide covers sites:** two new pages, [Your site](docs/user-guide/en/sites.md) (the site manager, section by section) and [Publishing and serving](docs/user-guide/en/publishing.md) (Publish, what a published site holds, serving it with sign-in), and screenshots of the editor and the site manager. *Sites, pages and the notation* is now *Pages and the notation*, and the parts that described older menus are up to date.
- In the site manager, a page's address that wraps under its name no longer starts indented.
- **Fixed: a page's files could be read half written.** Files were written in place, so another process reading one at that moment (the editor while Kaity's MCP server saves, or the other way round) could find it empty: a test failed now and then with "empty expression" on `layout.slice`. Every file of a page, and `site.json`, is now written under a temporary name and renamed into place, so a reader gets the old file or the new one.
- **Fixed: a wrong address on Cloudflare Pages went deeper and deeper** (`/munich2/munich/munich/…`). Without a `404.html`, Cloudflare Pages served the site's `index.html` for any unknown address, and its redirect to the home page is relative. Site exports now include a `404.html`: the list of pages under *This page isn't here*, whose links work at any address (a `<base>` from the site's address). GitHub Pages and Netlify use it too. It ends with the TYKERF mark and a link to TYKERF's repository.
- **Site icons (favicons).** Every site has one: by default made from the home page's first letter on the theme's accent colour (`favicon.svg`), or your own SVG, PNG or ICO, uploaded under *Styles & scripts* in the site manager (kept at the site's root as `favicon.<ext>`). Every page links to it, and exports and publishes include it. TYKERF's own screens (the site manager, sign-in, *not found*) and pages open in the editor show TYKERF's mark in the tab instead; visitors see the site's icon.
- **"Made with TYKERF" on published sites.** Publish adds a small line at the bottom of every page (the mark and a link to TYKERF's repository; its styles inline, in the theme's colours and fonts), and the same link under the list of pages. A checkbox in the Publish panel turns it off (`"credit": false` in `site.json`). Exports you download don't have it.
- **Fixed: Kaity going round in circles over a picture.** She couldn't add a picture, so she made up file names (`/assets/marienplatz.jpg`) and tried again after each broken screenshot. Now a box that uses a file the page doesn't have gets a warning at once (and `check_page` lists it), and a new tool, `add_picture`, saves an SVG she draws or a picture you attached to the request into the page's `assets/`.
- **Fixed: signing in behind an HTTPS proxy.** TYKERF refused every change, signing in included, when the browser reached it at an `https://` address (Caddy, nginx); it now accepts changes from `TYKERF_PUBLIC_URL`'s origin.
- **Export this page…** in the Site menu exports only the page you're on, with the site's theme and fonts, and lists its links to the other pages first (`/_tykerf/export.zip?page=<name>`).
- **The list of pages** (`/pages/`) shows each page's address under its title, marks the home page, and ends with the TYKERF mark and the way in (*Sign in to edit* or *Site manager*).
- **Styles & scripts for every page** in the site manager: the site head's code without its theme, with its own undo.
- **Serving a site to visitors.** With `TYKERF_ADMIN_PASSWORD`, visitors get the pages without the editor and every editor address is closed; the admin signs in at `/_tykerf/login`, linked from the bottom of the list of pages (*Sign in to edit*, then *Site manager*). See DEPLOY.md.
- **The trash.** The site's home lists the removed pages (in the site's `.trash` folder) with when they were removed, and **Empty the trash** deletes them for good, after asking.
- **Rename and remove pages while Kaity works.** Only the page Kaity is working on, and renaming a page that page links to, wait for her to finish (each with a message that says which); before, any Kaity run held every page.
- **A page like another one.** Kaity can now make a page like another page of the site (`use_page`: its blocks, code and images, and its theme when asked), and is told the site's other pages; *"a page about Munich like Rome"* starts from Rome instead of a layout. Claude Desktop's `new_page` takes `copy` for the same. Kaity's runs no longer see the site-wide page tools, which they could never use.
- **The site's home.** A site's own address (`http://localhost:4400/`) no longer jumps to its first page: it lists the pages, each with **Rename** and **Remove**, and **+ New page**, which opens the ways to start one step by step. The button that makes the page stays in sight at the bottom of the steps however short the window is (in *New page…* too). The page list in the editor has **All pages** to go back to it, and removing a page goes there too.
- **Claude Desktop works on a whole site.** Set the extension's *Page folder* to a site (a folder of pages), to one of its pages, or to an empty folder: Claude lists the pages (`list_pages`), opens the one you name (`open_page`) and makes new ones next to them (`new_page`, from a layout and a theme). It no longer starts a page right in a folder that holds pages, which would hide them.
- **The start screen follows its folder.** When something else makes the page in the folder the editor shows (Claude Desktop, the command line), the editor opens it by itself instead of staying on the start screen; pages made in its subfolders meanwhile are offered there, above the ways to make a new one.
- **Start a page from Claude Desktop.** The extension's *Page folder* can be an empty folder: ask Claude for a page and `use_layout` starts it there, with the theme it picks (`theme`, from `list_themes`). In a folder with no page yet, every other tool says how to start instead of failing.
- **A page folder with a space around it works.** The MCP server (and the Claude Desktop extension's *Page folder*) trims the folder it is given, so a path pasted with a space no longer fails with `mkdir '/ /Users/…'`, and it says in its log when the folder is not a TYKERF page.
- **Kaity finishes what she leaves behind.** After each request, TYKERF lists what that request left unfinished: sample text and pictures from layouts and components, and links that go nowhere or to a section or page that doesn't exist. What you had already left that way is never listed. **Fix them** asks Kaity to finish them; **Leave them as they are** keeps them for good. When Kaity builds a whole page, she gets one pass over the list herself before she finishes. She no longer makes up addresses for pages that don't exist yet: she asks whether they will be made. The same check is an MCP tool, `check_page`.
- **Follow Kaity's steps as she works.** The list of steps in the Kaity tab no longer folds up every time a new step comes in: while Kaity works, the current list is open and grows; a list you open or close stays that way; and the chat only scrolls to the newest line when you are already at the bottom.
- **Neutral names and text for the data page.** The *Paris* layout is now **Factual** (`factual`), and its headline, figure cards, bar chart, highlight, timeline and picture banner say what to write instead of telling the story of Paris. The *Paris* theme is now **Warm** (`warm`); the retired *Warm* theme in `Other_Layouts/` is now *Warm classic* (`warm-classic`). Pages made with them keep their content; a page whose theme came from *Paris* no longer shows the preset's name in the Page tab.
- **A page that isn't there any more** (renamed or removed, often in another tab) now gets a proper page instead of one line of plain text: it says what probably happened and where a removed page went (the site's `.trash` folder), and lists the site's pages to open.
- **A neutral header and footer.** The header every layout starts with no longer reads like a product launch page (Your brand · Product · Pricing · Customers · Blog · Get started). It now says what to write: *Site name*, *Page one* to *Page four* and *Contact*, which fits a blog, a shop, documentation or a portfolio as well. The footer follows: *Site name*, columns *Section one*, *Section two* and *Legal*. Pages made before keep their header and footer.
- **A model request that never comes back no longer hangs Kaity.** With the API runners, one model turn may take 3 minutes; then the run stops and the chat says *the model did not answer within 3 minutes; ask again to continue*. Set `TYKERF_TURN_TIMEOUT` (seconds) for a slower model or endpoint.
- **Continuous integration.** Every push to `main` and every pull request runs the type check and the tests, Chromium included (`.github/workflows/ci.yml`). Each published GitHub release gets the Claude Desktop extension, `tykerf.mcpb`, attached (`.github/workflows/release.yml`).

- **Kaity.** TYKERF's assistant now has a name, Kaity (Tydal's is Aity), and a symbol: eonity's three-ball isotype, which pulses while Kaity works. The AI tab is the *Kaity* tab, with a line saying which block Kaity works on and which model answers; *Ask Kaity* sends. The start screen, the build window, the Site menu and the messages say Kaity too.
- The start screen no longer waits for `claude --version`: whether Claude Code is installed is found out in the background when the editor starts.

- **Watch a page being made.** With *Show or describe it* or *A copy of a website*, the new page opens at once with a window that follows the work step by step (the AI's actions, or the copy's stages), while the page fills in behind it. The page can't be clicked meanwhile, so nothing disturbs the AI. The **×** stops the work: what the AI built stays; an unfinished copy is removed. At the end: the AI's summary, a short guide, and **Open the editor** or **See the page** (with *Edit with TYKERF* pointed out for later).

- **"Layout" instead of "template".** Ready-made pages are now *layouts*, the word TYKERF is built around: the start screen offers **A layout** and **Pick a layout**, the guide is *Layouts, components and the theme*, and the command line takes `--layout` (`npm run cli -- layouts` lists them). In the code, `templates/` is now `library/` (layouts, components, themes and fonts), `pages.json` is `layouts.json`, `src/templates.ts` is `src/library.ts` (`pageLayouts`, `PageLayout`, `libraryAsset`) and the editor serves `/_tykerf/library`. Box types keep their `template` (a box type's starting code).
- The start screen numbers its steps: 1 the page name, 2 how to start, 3 what to start from, 4 the theme.

- **Reset to a preset.** TYKERF remembers which preset a theme came from: the Page tab highlights it, says *changed* once you edit a value, and offers **Reset to …** (one undo step).
- The Page tab groups the theme values (*Colours*, *Type*, *Shape and space*), shows their full names, and keeps the columns apart on wide panels. Its actions sit at the bottom right, like *Save head*.

- **Bands and density in the panel.** The Size tab is now **Size & look**, and a block's **Band** (None, Alternate, Soft, Dark) and **Density** (Normal, Dense) are set there. The Blocks tab shows them for each block. Bands now paint any block, including boxes with their own code and whole containers, not only ready-made components.

- **A smaller, more varied set.** Five themes, each a different style: *Studio* (airy), *Product* (now packed: tight sections, a wider page, bold headlines), *Ivory* (editorial), *Gallery* (soft) and a new *Dark* for developers (near-black, mint accent, monospaced details). Eight templates that differ in layout and density, with two new packed ones: **Magazine** (a front page of stories) and **Catalogue** (a grid of products or services). New components: *Story grid*, *Card grid* and *List*. A new `#dense` tag packs any section tighter.
- **`Other_Layouts/`** keeps what TYKERF no longer offers (*SaaS landing*, *Landing page*, the *Clean*, *Warm*, *Bold*, *Editorial* and first *Dark* themes, the *About* component) and two layouts from TYKERF's roots in chip floorplans: a **pinwheel** and a **periphery**. Any of them can be brought back; existing pages are unaffected.

- **A page can set its own theme values** over the site theme: *This page only* in the Page tab, with each value marked *site* or *this page*, a *reset* per value and *Use the site theme again*. Only the values that differ are kept, so a page still follows the site for everything else.
- **The Page tab says where a page's look comes from:** inherited from the site, inherited with values of its own (named), its own theme, or a copy's own look.
- Theme presets rebuild the whole theme from TYKERF's current one, which brings older pages up to date and repairs band colours left behind by an earlier bug (switching presets, for example from Ivory to Gallery, could leave some colours unchanged).
- The theme values in the Page tab line up in columns, and *make auto* says what the button does.

- **Start with the AI.** The start screen and *New page…* now lead with **Show or describe it**: write what you want and/or drop up to three pictures (a screenshot, a sketch, a mock-up), and the editor opens on the new page with the AI building it. If the AI isn't ready, the option says why and the other ways remain.
- **One theme for the whole site.** A new site's first page sets the site's theme, which lives in the site folder's `head.html` and is used by every page. Change it from the Page tab of any page, with its own undo. Older sites get *Use this theme for every page*. Copies of websites keep their own look, and the AI can't change the shared theme from one page.
- **New page like this one:** a new page with the current page's navigation, footer and theme, and one empty section.

- **New look for templates:** light, modern launch pages drawn from real sites. Four new theme presets: *Studio* (now the default), *Product*, *Ivory* and *Gallery*. New templates: **Product launch**, **SaaS landing** and **Company**; *Portfolio* and *Landing page* use the new look. Rebuilt navigation, hero, features, numbers, testimonials, pricing, FAQ, call-to-action and footer components, new *Hero, split*, *Statement*, *Logos*, *Feature* and *Updates* components, and every other component restyled. Light product mock-ups replace the grey placeholders.
- **Bundled fonts:** Inter, Manrope, DM Sans and Newsreader (SIL Open Font License). A page gets a copy of the ones its theme uses, so it never calls a font server.
- **More theme values:** type scale, heading weight and letter spacing, button radius, section spacing, alternate band, soft accent and dark band colours. **Band tones** `#tone-alt`, `#tone-soft` and `#tone-dark` give any section a tone, and a dark band turns its text light.
- Every template is checked in a browser in the main presets: text contrast on every band (WCAG AA), heading order, no sideways scroll on a phone.
- Fixed: applying theme values also overwrote same-named values outside `:root`.
- Fixed: a block selected while the page was refreshing could be unselected.

- **Pick the AI.** `TYKERF_RUNNER` in a `.env` file chooses who answers in the AI tab: your Claude Code (default), the Anthropic API or any Anthropic-compatible endpoint (`TYKERF_API_KEY`, `TYKERF_AUTH_TOKEN`, `TYKERF_API_BASE_URL`), or Gemini (`GEMINI_API_KEY`). Every runner gets the same tools, the same limit to the selected block and the same history. The tab shows which runner and model answer. See `.env.example`.
- **Claude Desktop extension:** `npm run build:mcpb` makes `dist/tykerf.mcpb`. Install it in one click, choose a page folder, and Claude Desktop edits that page with TYKERF's tools, using your Claude account. Screenshots work where Chromium is installed.
- **Export** a page or a whole site as plain files for any web host, from the Site menu (a .zip, *For a web server* or *To open from disk*) or with `npm run cli -- export <dir> <out>`. Links between pages and images become relative, so the export works anywhere. It reports links to missing pages and files still loaded from other servers.
- **The Site menu**, an icon between the TYKERF logo and the page name, holds what acts on the whole site: **Export…** (it shows what the export will hold and what to check first), and **AI status…** (which runner and model answer, whether it's ready, a **Test** request, and what the AI is working on). The Page tab is about the page only.
- **Rename and remove pages** with the small buttons next to the current page in the page list. Links to a renamed page change in every page of the site, as one undo step per page. A removed page goes to the site's `.trash/` folder.
- **Link to a page of the site** from the link box (⌘K) or the Text tab, which list the site's pages. Links between pages are written from the site root (`/about/`).
- **Copy a website from the editor:** *Start from: A website* on the start screen and in New page…, and *Import a section…* for a box, which shows the page's sections with a picture of each. Both show the copying advice. Copies of 10 real sites no longer scroll sideways and keep their widths, floats, icons and hidden labels.
- The MCP tools are built by `createTykerfServer` (`src/mcp/tools.ts`), and Playwright is loaded only for screenshots and checks.

- **The editor and the AI can't overwrite each other's changes.** Every change takes a short lock on the page folder, so the editor, the AI's MCP server and other clients each read and save a whole step.
- **While the AI works on a block, the editor can't change that block**, and undo and redo wait for the run to end. The rest of the page stays editable.
- The AI's scope for an editor run is passed to its MCP server instead of being written to `.scope`, follows the block when the AI renames it, and refuses every change if the block disappears (before, the limit was silently lifted).
- A group of changes (Delete, Paste, Use a component) now happens whole or not at all: if a later part is refused, the earlier parts are undone.
- The history keeps the last 200 undo steps; older entries move to `.history-archive.jsonl` (label, author and time only), so large pages stay fast.
- Reading one box no longer reads every box (faster editor and MCP replies on big pages).
- MCP: `get_content` and `set_content` accept paths and positions like the other tools; `normalize` is a validated move.
- The AI tab runs through a `Runner` interface (`src/editor/ai.ts`); Claude Code is the first runner.
- SECURITY.md and the user guide explain that box scripts run in the editor with the editor's access, outside the AI's scope.
- **The AI can use components** (MCP `list_components`, `use_component`): it starts new sections from the ready-made components and adapts them, instead of writing them from scratch. Adding the theme variables to a page that has none needs the whole page in scope.
- **Editing in place.** Double-click text on the page to change its words, with bold, italic and links (⌘B, ⌘I, ⌘K or a small toolbar); what the browser types is cleaned on save, so no styles or extra tags reach the box's code. Double-click an image to replace, crop, turn or scale it down; the result is saved as a new file in `assets/` and only the image's address changes. Each is one undo step.
- **Sites of several pages.** A new or empty folder is a site: `npm start -- my-site` opens a **start screen** where the first page gets its name, template and theme, with a live preview at desktop or phone width. Each page is a subfolder with its own address in the editor (`/home/`, `/about/`); the **page switcher** next to the TYKERF logo lists them and adds pages with **New page…**. A folder that is one page works as before. `cli render <site>` renders every page.
- **Theme presets:** *Clean*, *Warm*, *Dark*, *Editorial* and *Bold* (`templates/themes.json`, installed fonts only), on the start screen, in New page…, in the Page tab (one click, one undo step) and as `--theme` for `npm start` and `cli new`.
- Fixed: *Add below* on the top block wrapped the whole page in a new column (`o1`). The top block now offers *Add inside* only, and adding next to the root (Paste, MCP) puts the box at the end of the page when the page runs that way.
- **Narrower blocks:** a handle on the right edge of the selected block (and a slider in the Size tab) makes it narrower and centred. It's the block's `maxw` in the tree, so the code doesn't change; this is how an Image box shrinks its picture.
- **Image component:** one picture with a caption that fills its box, so the box handles set its width and height.
- The image tool keeps the original of every crop (`.images.json`): opening a cropped image shows the whole original with the crop on it, so a crop can be widened or undone later. The crop frame has edge handles (only the width or only the height), and *Start over*.
- The context menu does small things on the page: *Edit this text*, *Edit image…*, *Rename…* and *Delete…* open next to the pointer instead of in the panel.
- The editor serves page files with `Content-Security-Policy: sandbox`, refuses requests over 25 MB, and accepts uploaded images only as PNG, JPEG, GIF, WebP or AVIF (checked by their bytes).
- Fixed: when the AI renamed the block it was working on, its conversation stayed under the old name and the editor locked the whole page until the run ended. The conversation, the lock and the panel's selection now follow the block.

- The panel header shows the full logo (mark and the "tykerf" wordmark), divided from the path.
- **The AI can change the theme** (MCP `get_theme`/`set_theme`): only the theme's values, each checked, and only when the whole page is selected.
- Theme: *Bands and cards* and *Lines* follow the background colour unless set (marked *auto* in the Page tab).
- Fixed: dragging the panel past the edge of the window selected the whole page.
- **Templates and components:** start a page from a template (`--template blank|landing|article|portfolio|docs`, `cli new`, `cli templates`), and fill an empty box with one of 17 ready-made components. All share one theme of CSS variables.
- **Page tab** on the top block: edit the theme (colours, fonts, spacing) and the page's head code; undoable, and open pages reload.
- Pages have an `assets/` folder for images, served by the editor and copied to `out/assets/` when rendering.
- **Redo:** undone changes can be brought back (the arrow next to Undo, ⇧⌘Z or Ctrl+Y, and the MCP `redo` tool), until a new change is made.
- Pages live in a `Store` (`src/store.ts`): a folder or memory today, with S3 or Tydal as future backends. Everything that reads or writes a page goes through it, and store paths can't leave the page (a box type's template can no longer point outside it).
- The editor interface is ready for translation: every string goes through `t()`, with catalogs in `src/editor/public/i18n/<lang>.json` (English for now).
- Docs follow the eonity layout: `DEPLOY.md`, `BRAND.md`, `ROADMAP.md` and `NOTICE` (now with trademark terms) at the root, and a user guide in `docs/user-guide/en/`.
- `import` prints advice on what you may do with a copied site.
- The editor accepts IP-address host names when shared with `--host`.
